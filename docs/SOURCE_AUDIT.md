# Source audit and selection

Candidates were cloned and inspected at the following revisions. Non-adopted code was not copied and was not claimed to have passed our integration tests. Decisions concern this architecture, not general assessments of upstream quality.

| Candidate / revision | Finding and decision |
|---|---|
| [skelerealms](https://github.com/SlashScreen/skelerealms) · `293dfd0b68541066bc505eadf03255d85218b4bf` | Inventory/equipment use SKEntityManager, ItemComponent and data components; navigation/GOAP execution assume NavigationAgent3D and SKEntity. Importing that world registry would conflict with the selected 2D C# actor owner. Extracted its independent planning graph instead of importing competing entities. |
| [open-rpg](https://github.com/gdquest-demos/godot-open-rpg) · `d59f2f71bc046ac53239a4e590861269e7100a36` | Inspected field interactions, scene/autoload setup and combat source. Turn-based arenas, Dialogic integration and 4.7 project requirements would require replacing the action pipeline and selected dialogue owner. No demo assets copied. |
| [abilities](https://github.com/LiGameAcademy/godot_ability_system) · `362fa1df1586ef0f39e1bd516398df26b241bc0c` | 192 scripts including components, feature-driven behavior trees and singleton services. Viable but duplicates the engine-independent SPELL execution/state owner already selected alongside native PPC. Chose one ability pipeline; no claim this candidate is broken. |
| [health](https://github.com/cluttered-code/godot-health-hitbox-hurtbox) · `c9d21850e6fa60a67f6a3ff0dac889bf803d06ad` | Provides typed HealthAction/HurtBox/Health nodes. Not imported: the selected SPELL adapter resolves directly to persistent actor health and geometric world hit queries. A second node-owned health representation is unnecessary for this foundation. Custom damage/mitigation is the required gameplay adapter, not a port of this addon. |
| [inventory](https://github.com/expressobits/inventory-system) · `f716e2c1d762988ca37bdc92a2fdc4df29a7835c` | Main branch is C++ GDExtension; the C# branch contains wrappers around native classes, not a standalone managed inventory. Selected pure-GDScript Gloot with real stack/slot serialization instead. |
| [itemanvil](https://github.com/rmMinusR/ItemAnvil) · `11cc5600a7cff86c003d724ca4dd7548ed144b8c` | Unity ScriptableObjects, UnityEngine InputSystem and TextMeshPro are concrete runtime/editor dependencies. Gloot provides native Godot inventory without a Unity port. |
| [gaea](https://github.com/gaea-godot/gaea) · `79461f6491e796bc50939babceb14d34f019a588` | Graph/node generation framework with 166 scripts and editor integration. Not a complete RPG region/mission generator. Selected Godot FastNoiseLite for regional fields and the complete mission/layout grammar subsystem for dungeons; importing an unused graph editor would not increase integrated capability. |
| [aithena](https://github.com/sa-aris/aithena) · `4cde155cdcf17875c5510065a1fbf06cfeeb8e63` | C++17 simulation/AI with vcpkg dependencies; not a Godot actor component. A native binding and second actor/economy model are disproportionate to the common C#/GDScript action boundary. |
| [planning](https://github.com/WahahaYes/GdPlanningAI) · `f81b862a7d3b4c024b1bf9f3bf9875d17bbe694b` | Current source/toolchain targets newer Godot and adds native Rust planner integration. Extracted engine-native Skelerealms planner avoids another compiled extension. |
| [limbo](https://github.com/limbonaut/limboai) · `a2d2ea34732bd6d60de99f5cf60b21b707e6d221` | Substantial C++ behavior-tree/blackboard/agent implementation. Requires engine module or matching GDExtension binaries for every target. Existing deterministic planner is adequate for the initial data-driven schedules/combat profiles; keep a single AI owner. |
| [trees](https://github.com/Desarrh/Procedural-Tree-Godot) · `5c1abe648f3b807d46cfe4fb4af717be4d4ea8bd` | Pure Godot procedural tree script evaluated. PPC already supplies consistent environment art at creature pixel density. No competing vegetation authoring/rendering path imported. |
| [grass](https://github.com/Desarrh/Procedural-Grass-Godot) · `e711ad3247a9e44b489afc93e9e003ac0cfa2f7b` | Pure Godot swaying vegetation script evaluated. Optional visual feature; no dependency needed for collision/navigation/resource foundations. |
| [fx](https://github.com/GameDev-Toolkit/pixel-ability-fx-generator) · `7898827adc524bbc02b3fa9ecb61cff84e0761ce` | Apache-2.0 procedural VFX authoring project; evaluated as tooling, not imported. Current project uses native projectile/hit feedback and gdfxr for reproducible audio. Additional authored spell effects remain content work. |
