# Creative direction — making Mosslight feel like *a game*, not a test harness

Ross gave this redesign full creative freedom. This document uses it. Parts 1–4 build a clean, usable foundation; this document adds the features that give Mosslight an identity. Each feature is assigned to a part, with enough specification to implement it.

**Where this document overrides the part guides:** the HUD layout (C3 replaces PART2 §1–2), action IDs (C5), Trade (C8 replaces D5), the death flow (C11 replaces PART4 §2 "Defeat") and the boot flow (C1 replaces the initial Pause). The part guides now point here at those sections.

## What actually constrains us (and what doesn't)

Nothing in the earlier guides is sacred. Tests, log formats, smoke scripts, save fields, the `.tscn`-free convention and action IDs can **all** change. A few rules remain, because they prevent bugs, not because they limit creativity:

1. **One owner per fact.** Gloot owns items, `Narrative`/QuestSystem owns quests and journal flags, and `World` owns actors and regions. UI may cache *presentation* (textures, layout), never game facts. Duplicated state is how this project's earlier reward and crafting bugs happened.
2. **Change a contract and its consumer together.** If a test, smoke step or log format no longer fits the design, rewrite it in the same commit so it checks the new intent. Never delete coverage to get green.
3. **Saves stay loadable.** New save data must be additive with defaults, and include a test that loads an existing pre-change save (`docs/*evidence*` and the legacy-save checks already do this).
4. **Phone first.** Touch sizes, safe area, and no accidental input during combat.

## The pitch

> *A lantern-lit field journal for a world that grows itself.*

Mosslight's unique asset is that **every creature is procedurally generated and rendered live (PPC)**. The current UI never shows them except in the world. The creative core of this redesign is to put those creatures into the interface: a live hero portrait that wears what you're about to equip, dialogue with the speaker's real face, and a codex that fills with the creatures you've met, each rendered from its actual genome. Around that sit a living title screen, pixel-art UI frames generated by the same procedural philosophy as the environment, a minimap, readable combat numbers, a real economy, and a death screen that teaches.

## C1 · The Lantern Gate (title screen) — Part 1

**Why:** the game currently boots into a developer-style pause list labelled "Enter / Resume". The first screen sets the tone.

**Look** (mockup [`11-title.svg`](mockups/11-title.svg)): the real Reach behind the menu. Creatures idle and breathe (unpause their animation only; `World` does not tick). The camera drifts slowly along a 40-second looping path over the settlement. A dark radial vignette and a soft lumen glow surround the logo.
- Logo "Mosslight" in Alegreya SC, 76 lp, gold with a 2 lp dark outline and a lumen outer glow that "breathes" (alpha 0.5↔0.8, 4 s; static with reduced motion). Tagline: "A light lies buried beneath the Reach." (`CaptionLabel`, `text.secondary`).
- Left column at `safe.X + 80`, vertically centred, width 460:
  1. **Continue card** (primary, 132 lp tall): player portrait snapshot (C6) · "Wayfarer · Level 3" · region · current quest stage · "Saved 2 Nov, 14:32". It picks the most recent of slots 1–3 and the autosave (by sidecar `saved_unix`, PART4 §2), labelled "Continue (recovered)" when it's the autosave. Hidden when no save exists.
  2. **New adventure** (primary when no save exists, else secondary; confirm if a save exists).
  3. **Load game ›** (Save/Load screen in Load mode).
  4. **Settings ›**.
  5. **Quit** (desktop only).
- Version caption bottom-right: `BuildIdentity.Source` short SHA.

**Flow:** selecting Continue or New fades the menu out (`motion.slow`), eases the camera back to the player (600 ms), and shows the region title card (PART2 §6). After the first session starts, Esc/Back/Menu open the normal Pause, never the title. A "Return to title" row in Pause (with confirm) takes you back.

**Implementation:** `TitleScreen : UiScreen` (family `Title`, not `Pause`, so `MenuOpen` stays false and `CanManageItems` is unaffected; `BlocksInput` is true). Foundation gets `public bool TitleMode`. While true, `_PhysicsProcess` skips the world tick (already true via `GameplayBlocked`). Views get `Creature.Paused = false` for living actors in the current region, and `TitleCamera` drives `camera.Position` along a Catmull-Rom path through 5 points around the settlement centre. Verification mode: no drift, fixed camera, Continue card from a fixture.

**Contract updates:** the Android smoke taps `title_continue`/`title_new` instead of `pause_resume`. `ReviewChecks`' initial-menu loop becomes: title → Continue/New → gameplay; Escape at title does nothing (Back on the title asks to quit on desktop and is ignored on Android). The background-before-session check ("untouched initial menu does not overwrite a recovery save") stays and applies to the title.

## C2 · Brass & Moss — generated pixel-art UI skin — Part 1

**Why:** flat rounded rectangles read as "generic app". The world is pixel art, generated procedurally (`EnvironmentArtGenerator`). The UI frames should come from the same family.

**What:** `UiSkinGenerator` builds a small set of 9-slice textures at startup, deterministically (seeded integer hash, no RNG state), cached like `EnvironmentAssetCache`:

| Texture | Size (texels) | Description |
|---|---|---|
| `panel` | 48×48, margins 16 | 2-texel dark outline, 3-texel brass bevel (light top-left `#E8CF8A`, dark bottom-right `#7A6232`), inner 1-texel shadow, `surface.1` fill. Corners get a 5×5 rivet/filigree motif. 2–4 moss tufts (3–6 texels, two greens `#5E8A3A`/`#8DB65A`) grow on the top edge near the corners, positions from the hash |
| `button` / `button_pressed` / `button_disabled` | 32×32, margins 10 | brass rim, `surface.2` fill; pressed inverts the bevel and shifts the fill down 1 texel; disabled desaturates the rim |
| `button_primary` | 32×32 | gold fill with a darker gold rim and a 1-texel highlight row |
| `slot` | 32×32 | sunken well: dark inner bevel, for item tiles and equipment slots |
| `slot_selected` | 32×32 | slot + 2-texel gold frame with corner sparkles |
| `tab_active` | 32×16 | gold underline with small leaf terminals |
| `plate` | 32×32 | HUD back-plate: translucent `hud.plate`, thin brass hairline |
| `divider` | 32×4 | brass line with a centre diamond |

- Draw at **2 lp per texel** (`StyleBoxTexture` with `texture_margin_*` = margin, `axis_stretch_* = Tile` for edges). Set `TextureFilter = Nearest` *on skin styleboxes only*, so frames stay crisp pixel art while icons and text stay smooth (DESIGN_SYSTEM §7).
- **Region variants:** `Reach` (brass + moss, above) and `Ruin` (cold stone rim `#8A948F`/`#3D4643`, lumen rune dots `#9FE3E6` instead of moss). The Book and HUD swap variants on `region_entered`. The swap is just a theme rebuild, with no relayout.
- **High-contrast** setting (PART4 §3) falls back to the `StyleBoxFlat` recipes in DESIGN_SYSTEM §5.
- Tests: generation is byte-identical across two runs and takes < 30 ms; every texture's margins leave a ≥ 1-texel stretchable centre.
- Mockups approximate the skin with vector strokes; the in-engine result should look more textured.

## C3 · HUD v3 layout — Part 2 (replaces PART2 §1–2 geometry)

Mockup [`01-hud-mobile.svg`](mockups/01-hud-mobile.svg). It adds a **minimap** top-right, stacks Book/Menu beside it, and moves the **quest tracker under the vitals** on the left (away from the right-thumb action fan). The layout has two height tiers.

Let `s = min(1, safe.W/900, safe.H/560)` and `a = s × ButtonScale` (action fan only). ButtonScale applies only if `safe.H / (s × ButtonScale) ≥ 640`; otherwise it falls back to 1.0.

**Tall tier** (`safe.H / a ≥ 640`):

| Element | Rect | Notes |
|---|---|---|
| Vitals | `(L+24, T+20)` 432×110 ×s | |
| Quest tracker | `(L+24, T+146)` 360×112 ×s if `safe.H/a ≥ 720`, else 80×80 icon | tap → Journal |
| Minimap | `(R-200, T+16)` 176×176 ×s | tap → Book ▸ Map |
| Book (`inventory`) | `(R-292, T+20)` 80×80 ×s | |
| Menu | `(R-292, T+112)` 80×80 ×s | |
| Toast lane | between the vitals' right edge + 16 and the Book button's left edge − 16 | fallback under the tracker if span < 360 |

**Short tier** (otherwise): minimap 112×112 at `(R-136, T+16)`; Menu `(R-320, T+20)`, Book `(R-228, T+20)`, tracker icon `(R-412, T+20)`, all 80×80; vitals 432×96 (status chips move inline to the right of the mana bar, max 2).

**Action fan** (unchanged shape from v2, new IDs per C5; `At(right, bottom, w, h)` × a): `attack (172,172,136,136)`, `dodge (330,150,108,108)`, `skill1 (300,282,92,92)`, `skill2 (156,330,92,92)`, `skill3 (260,430,88,88)`, `potion (446,214,88,88)`, `interact (480,384,184,80)`. The stick is `(L+40, B-260)` 200×200 ×s. Left-handed mirrors the fan and the stick only.

`docs/ui/mockups/check_geometry.py` verifies **160 layouts** (10 window sizes × 4 safe-area insets × both hands × ButtonScale 1.0/1.15): every rect is inside the safe area with gaps ≥ 12·s. Port that table into `HudChecks.cs`. `MobileCombatControls.LayoutVersion = 3`.

**Minimap** (rounded square, `clip_contents`, skin `plate` frame with an "N" notch at the top):
- North-up and fixed scale: 24 × 24 tiles visible (7.3 lp per tile at 176).
- Terrain from a cached `ImageTexture` of the region at 1 texel per tile, drawn with nearest filter and offset so the player is centred. Rebuild only on region change or when `ExploredTiles.Count` changes (ruin fog). Colours as the Book map (PART3 §7).
- Markers: player arrow (gold, rotated by facing) at the centre; **objective pip** (gold ring), clamped to the rim with an outward chevron when off-view; hostiles within 12 tiles that `World.LineOfSight` can see, as red **triangles** (shape, not just colour); the warden/merchant as a gold chat dot; lootable corpses as a small skull; opened/closed gates as in PART3 §7. Update markers at 10 Hz and the terrain only on change.
- Tap → `OpenBook(Map)`. Registered as action id `minimap` in `MobileCombatControls`.

## C4 · Combat text and enemy nameplates — Part 2

**Combat text** (`CombatTextLayer`, one world-projected `Node2D`, ZIndex above `CombatEffects`, drawn with `DrawString` in `_Draw` from a pool of 24 entries):

| Observation (`World.Presentation` events) | Text | Style |
|---|---|---|
| Hit by the player | damage, e.g. `14` | `text.primary` with a 3 lp ember outline; size 22 + 10 × min(1, dmg / target.MaxHealth × 3) |
| Player hit | `-9` | `danger.text`, dark outline |
| Heal (mend/potion) | `+12` | `accent.moss` |
| Miss | `miss` | 18, `text.secondary` |
| Dodge avoidance | `dodged` | 18, `accent.lumen` |

Text rises 28 lp over 700 ms with ease-out and fades over the last 250 ms. Simultaneous numbers on one target fan out ±14 lp horizontally. There's a setting toggle (default on). Text is presentation-only and doesn't replace the existing distinct hit/miss/dodge cues.

**Nameplates:** above a hostile that was damaged in the last 6 s, or that is the slash aim-assist candidate. A `CaptionLabel` 18 name ("Ruin brute") plus a 48 × 6 bar (`danger.fill` over `#2A1312`). At most 6, nearest first. Fade out over 400 ms. Elites (a future `CombatProfile` flag) get a gold rim.

## C5 · Action bar loadout — Part 2 (HUD) + Part 3 (Hero)

**Why:** the HUD hard-codes Ember and Mend, and newly learned abilities have nowhere to go. Let players build a kit.

- **Data:** `ActorState.ActionBar : List<string>` with three entries (ability IDs, `""` = empty). Default for new games and for older saves without the field: the first three known non-slash abilities in content order (today `ember`, `mend`, then `ward` if learned). Additive JSON field, plus a legacy-save test. `Progression.Unlock` auto-places a new ability into the first empty slot and publishes `action_bar_changed`.
- **HUD IDs:** `skill1`, `skill2`, `skill3` (each renders its slot's ability icon, cost, cooldown and label). An empty slot shows a dashed ring with `+` (tap → Book ▸ Hero ▸ Action bar). `RpgUi.ActionControl` accepts legacy aliases (`ember` → the slot currently holding `ember`, `ability3` → `skill3`), so old tests read naturally. Update the smoke and checks to the new IDs anyway.
- **Keys:** `1` Sword · `2 3 4` skill slots · `Q` Draught · `Space` Dodge · `E` Interact · `I C J M` Book tabs · `Esc` menu. Update `README.md` and the `Foundation` bindings.
- **Hero ▸ Action bar** (mockup [`04-book-hero.svg`](mockups/04-book-hero.svg)): three large slot cards at the top. Tap a slot (gold selection) → the ability list below highlights assignable known abilities → tap one to assign (swap if it's already in another slot). On desktop, drag-and-drop works too. Changes go through a new `World.SetActionBar(actor, index, abilityId)` command (validates that the ability is known and not slash), routed through `App.ManageItem`-style gating.

## C6 · Live creature portraits — Part 3

`CreaturePortrait : Control`. It hosts a `CreatureActor` (from `PixelCreatures.Runtime`) as a child `Node2D`, with `CullOffscreen = false`, `AnimationFps = 10` and `Quality = 1`, centred and scaled to fit the control (`Model.Anatomy.Metrics.BodyLength`), on `clip_contents`.

| Use | Mode |
|---|---|
| Hero page (200 × 240 portrait) | **Live**: idle animation plus a slow turntable (yaw 0.25 rad/s; drag to rotate on Touch; static facing with reduced motion) |
| Pack ▸ Equipped column (160 × 160) | Live, fixed three-quarter facing; used by C7 |
| Dialogue speaker (112 medallion) | Live, facing the text; the speaker's **actual** actor genome (`ActorState.Appearance`) |
| Title Continue card, Save/Load cards, Codex, death recap | **Snapshot**: render once, copy the creature's current frame into an `ImageTexture` cached by genome hash (LRU of 48) |

Budget: at most **3 live portraits** at once (the Book shows at most two). They render through the existing bounded PPC render queue, so measure the cost in the Part 4 performance pass. Use the player's *presented* genome (`App.Views["player"].Creature.Genome`, which includes gear), so portraits match the world.

## C7 · Try-on — Part 3

When an equipment item is selected in Pack ▸ Bag or the Trade page, the Equipped-column portrait shows the player **wearing the candidate**. Build the presentation genome with the same gear-variant path `CharacterView` uses for equipped items, fed a hypothetical slot map (current equipment with the candidate substituted). Factor that path into a reusable `GearPresentation.Variant(baseGenome, slotItems)` if it isn't already one. A small "Preview" chip appears over the portrait, and clearing the selection reverts it. This is purely presentation: nothing is equipped.

## C8 · Merchant economy — Part 3 (replaces D5)

Mockup [`13-trade.svg`](mockups/13-trade.svg).

- **Values:** add `"value"` (crowns) to every prototype in `items.json`: iron_sword 24, oak_staff 18, leather_coat 16, potion 6, herb 1, ore 2, wood 1. Mark `relic` and `dungeon_key` `"quest": true` (unsellable, untradeable). Coin has no value field.
- **Price function** (one static `Prices` class, unit-tested):
  `quality_mult = 1 + 0.25 × quality` · `condition_mult = condition/100` (default 1) · `rep_discount = 0 / 0.05 / 0.10` for Neutral / Friendly / Honoured with the merchant's faction.
  **Buy** = `max(1, round(value × quality_mult × (1 − rep_discount)))`. **Sell** = `max(1, floor(value × quality_mult × condition_mult × 0.4))`.
- **Merchant purse:** merchants hold real Gloot `coin` stacks. Seed 80 crowns where merchant stock is created. A merchant can't buy beyond its purse; the Sell button shows "The warden can't afford this (has 12)".
- **Transactions:** keep `Items.Trade(buyer, merchant, item, price)` for buying (now called with `Prices.Buy`). Add `Items.Sell(seller, merchant, selector, price)` with the **same snapshot/rollback discipline as `Craft`**: capture → transfer the item instance → transfer coins → on any failure, `import_state(before)`. Publish `traded` (sell) only on success.
- **Buyback:** items the player sells during the current Trade visit appear at the top of the merchant column tagged "Sold by you", purchasable at the *sell* price until the Book closes. Keep that list on the open `TradePage` only (visit-scoped presentation state, never saved).
- **Layout:** two columns, merchant stock (left) and your sellable items (right), each a list of rows (icon, name, quality pips, price chip). The selected row opens a details strip at the bottom with comparison and try-on (C7) and a **Buy** or **Sell** primary button. The header shows both purses ("You: 20 · Warden: 80") and the reputation discount chip ("Friendly · 5% off").
- **Tests:** a buy→sell round trip conserves total crowns between player and merchant; Sell rollback leaves both bags and purses semantically identical; quest items never appear as sellable; prices match the formula for every prototype.

## C9 · The Codex — Part 3 (Journal ▸ Codex)

Mockup [`12-codex.svg`](mockups/12-codex.svg). Journal's segmented control becomes **Quests | Codex | Lore**.

- **Creatures:** the first time a hostile or notable actor is within 200 ground units and in line of sight, record `flags["codex:creature:<profile>"] = {name, family, genome (GenomeJson if present, else family+seed), region, first_seen_day}`. Foundation polls every 30 ticks and calls `Narrative.codex_seen(...)`. Defeats come from the existing `defeated:<profile>` flags. **Observed attacks:** when an actor of that profile starts an ability within 200 units of the player, add the ability ID to `codex:creature:<profile>.attacks`.
- **Entry card:** snapshot portrait (C6), name, habitat, "Defeated ×4", and known attacks with a one-line counterplay tip from a `UiText.CounterTip(ability)` table (bite → "The bite tracks you — roll through the closing ring."; slam → "Brutes commit to the sweep — step out of the cone or dodge through it."; spit → "Droplets fly straight — sidestep after the release.").
- **Undiscovered** profiles (all profiles in `spawns.json`/`combatProfiles` minus seen) show as dark silhouettes, "???" and "Not yet encountered", with a completion counter "Creatures 3 / 5". That gives exploration a collector's pull without adding mechanics.
- **Places:** discovered landmarks and regions (`discovery:` flags) with the landmark icon and lore. **Items:** every prototype ever acquired (`codex:item:<id>`, recorded on `item_acquired`) with blurb and value.
- Everything lives in Narrative `flags`, so it's saved with no schema change.

## C10 · Ceremony — Part 2

- **Quest complete card** (mockup [`15-quest-complete.svg`](mockups/15-quest-complete.svg)): a non-blocking card, 520 wide, centred under the toast lane. A gold `DisplayLabel` "Quest complete", the quest name, and reward tiles (64 lp). After 1.8 s the reward icons **fly** along a quadratic arc (600 ms, ease-in) to the Book button, which does a 120 ms scale bump and gets a gold "new" dot. If the reward is pending (full pack), the tiles turn amber with "Waiting with the warden" and don't fly. Plays `ui_quest`. With reduced motion: fade, no flight.
- **Loot flight:** on `item_acquired` from a chest/node/corpse, a 32 lp icon flies from that world position (projected) to the Book button (400 ms). At most 4 in flight; extra items merge into the toast only.
- **New-item dots:** item tiles acquired since the Book was last opened show a gold dot (session-only presentation state).

## C11 · Fallen — death recap — Part 4 (replaces the PART4 defeat banner)

Mockup [`14-defeat.svg`](mockups/14-defeat.svg).

- On death, the world desaturates over 600 ms (a CanvasModulate tint toward `#6B6B6B`), the death pose plays, and after **1.5 s** the `FallenScreen` opens (family `Pause`, so `MenuOpen` is true and item management is blocked).
- Content:
  - "You have fallen" (`DisplayLabel`, `danger.text`).
  - The killer: snapshot portrait, "Slain by a **Ruin brute** · Crushing sweep". Use the last `World.Presentation` hit event whose target is the player; it carries the acting ID and ability ID.
  - A **tip** card from `UiText.CounterTip(ability)` (shared with C9).
  - Run stats: "Foes defeated: 5 · Rooms explored: 7 · Time: 12 min" (from flags/events since the last load).
  - Actions: **Load last save** (primary), **Recover autosave**, **New adventure**, **Return to title**.
- Update `MobileCombatControlsChecks` ("defeated player opens the menu by touch"): after death, wait for the recap and assert `MenuOpen`. Its intent (a dead player can always reach recovery) is preserved.

## C12 · Coach marks — Part 4

A `CoachMark` callout: a speech bubble (`surface.1`, gold border) with a pointer at a target control or world position, one short line, and a "Got it" ghost button. Each is dismissed by performing the action. At most one at a time, never during dialogue or combat (no hostile within 160), and never in verification mode. Seen flags live in `user://settings.cfg` (`hints.<id>`). Settings ▸ Accessibility gets "Reset tutorial hints".

| id | Trigger | Points at | Text (Touch / Desktop) |
|---|---|---|---|
| move | session start, no movement for 3 s | stick | "Drag here to move" / "Move with WASD" |
| attack | first hostile within 220 | attack | "Tap to swing your sword" / "Press 1 to swing" |
| dodge | first enemy windup targeting the player | dodge | "Dodge through attacks" / "Space to dodge" |
| interact | first actionable preview | interact | "Tap to open, gather or talk" / "Press E" |
| book | first loot | Book button | "New items in your pack" |
| quest | first quest accepted | tracker | "Your current objective — tap for the journal" |
| skill | first ability learned | the new skill slot | "Your new ability is ready" |

## C13 · Gamepad — Part 4

Add joypad events to every InputMap action. Left stick moves (with the existing dead-zone/curve), A attack, B dodge, X interact, Y draught, LB/RB/RT skill 1/2/3, Start pause, Select Book, D-pad/left stick navigate focus in screens, A accept, B back, LB/RB switch Book tabs/segments. Track the last input device (`touch | keyboard | gamepad`). Keycap chips and coach marks switch glyphs (drawn as round face buttons with letters; no trademarked art). Focus rings show for keyboard and gamepad. Android controllers work through the same map. Test: synthesised `InputEventJoypadButton` drives attack, dodge and menu navigation.

## C14 · Ambience — Part 2 (could)

The HUD clock caption gets a sun or moon icon by `World.Time`. Between 20:00 and 05:00 HUD plates take a 6% cool tint. The UI skin variant follows the region (C2). Region title cards get a one-line flavour subtitle from `UiText.RegionFlavour`.
