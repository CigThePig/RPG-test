# Architecture

`Foundation` composes the application. `World` owns authoritative actors, regions, clock, actions and the short event stream. It has no renderer-owned gameplay state. Godot ticks it at 60 Hz and routes UI/input into its public commands. `ActorState` contains persistent identity, action state, attributes, experience, skills/capability lists, faction, reputation, knowledge and relationships. A separate `Appearance` stores the original genome and generator identity.

## Imported implementations and authority

Gloot owns all item instances, stacks and equipment slots. The C# `Items` façade calls the real GDScript implementation; it has no parallel collection of items. Gloot property bags preserve material, quality, condition and IDs through transfers. `ActorState` owns health and resources. SPELL executes requirements, costs and effects compiled from `AbilityDef`; the adapter starts serializable windup/recovery states. Costs and cooldowns are committed only after validation. Immediate SPELL effects are drained when a cast begins, leaving no unpersisted pending library effects.

Melee uses geometric range and line-of-sight at resolution time. Projectiles advance through `ProjectileFlight`: legacy target-following, straight release headings or bounded angular homing; analytic actor and grid terrain sweeps select one earliest contact. Damage performs mitigation, recovery/invulnerability, knockback, interruption, death, XP and loot creation. Status definitions provide capped stacking, refresh, periodic damage and action-blocking hooks. Healing, items and attacks are shared player/NPC operations. Action state prevents incompatible movement/casting/use overlap. The verification-only cone demonstrates a bounded multi-target strike; circular area abilities remain extension work.

`CombatGeometry` contains stateless ground-space circle and cone tests. Target-locked abilities retain their existing target/range/line-of-sight checks. An authored cone commits its direction in `BeginAbility`, resolves against the same range and angle as its warning, and calls the existing damage/status pathway in ordinal actor-ID order. The player's separate free slash and its reach/selection rules are unchanged.

`World.Presentation` publishes immutable `CombatPresentationEvent` values with kind, acting and target IDs, ability ID, tick, ground origin/position, direction and outcome. Start and commitment follow successful activation; direct impact or projectile release follows windup; hit, miss, defensive avoidance and death are observations of world decisions; cancellation and recovery completion describe lifecycle boundaries. Projectile collision is distinct from release. Hit positions are captured before knockback. A single `CombatPresentationController` subscribes to that stream and routes each observation to actor views, a bounded effect layer, cached audio and camera feedback; the diagnostic trace and narrative `World.Events` remain separate. No presentation subscriber applies gameplay outcomes.

`TelegraphView` is one ground layer that derives warnings and progress from live actor windup, remaining time and ability definitions. It owns no action timer and reconstructs from world state after views or saves are rebuilt. The minimum visible windup is a presentation threshold, not a gameplay delay. Impact, interruption, death and region changes make warnings disappear. Schema 1 remains valid; the optional recovery ability ID supports completion events without replaying impacts.

QuestSystem owns quest lifecycle/pools. `EventQuest` adds event/objective counters and failure/reward metadata. Dialogue Manager compiles the ordinary upstream dialogue format; its mutations call the same narrative API. `Narrative` observes a scoped stream emitted by the current world and emits explicit reward/reputation requests back to the composition root. Completion cannot grant the same reward twice after restoration. No unrelated subsystem looks up another through an enormous global bus.

## NPC execution

The extracted Skelerealms GOAP graph plans against value-aware conditions. The production adapter supplies combat, retreat, rest, trade and patrol goals. Schedules, perception range, line-of-sight, faction relationships, health and ability constraints select current goals. Navigation routes through the authoritative region cells. Motion is continuous at the fixed tick; planning is throttled to 5 Hz. Distant/unloaded inhabitants retain schedule/state with a coarse schedule update, rather than inventing offscreen battles or economies. `CombatBrain` chooses approach, hold, valid local retreat/circle or an eligible weighted ability beneath the planner. Profile cadence, target retention and distance hysteresis stabilize intentions. `ActorSeparation` uses stable snapshots in reusable regional buckets; only ordinary NPC locomotion receives soft steering, with terrain-checked fallback and a normal-speed cap. See `PR4_PART4_HANDOFF.md` for profile, projectile, persistence and diagnostic contracts.

## Procedural world

Godot FastNoiseLite generates repeatable regional fields with settlement/causeway constraints. Region tiles drive collision, water traversal, line-of-sight, paths and rendering. Graph Dungeon Generator supplies the original mission grammar and spatial layout. The adapter builds rooms/corridors, places keys/doors/rewards, corrects the upstream reversed door convention and validates actual tile-level key/lock reachability with bounded state search. Invalid layouts are rejected with bounded deterministic retries. Spawn tables select families/abilities and create stable region actor IDs. Dungeon state is retained when leaving.

## Presentation

`AnatomyAdapter` derives wings/fins/arms, collision dimensions and movement/equipment capabilities in the model layer, including actors that have never been rendered. `CharacterView` consumes that state and original PPC genomes; pixels never decide capabilities. Existing equipment is reconciled after anatomy changes and save restoration. Equipment produces a presentation-only genome variant through PPC gear genes. The base saved appearance stays separate from equipped items. PPC's factory cache and original render queue retain CPU rasterization, parallel batching, 10-fps pose presentation, offscreen culling and engine texture updates. Unloaded actors stop detailed presentation.

`RpgUi` panels are views of live state. Dialogue uses its own modal panel driven by actual dialogue resources. Region terrain is one retained draw-command node per active region, avoiding rebuilding it every frame; features/projectiles are dynamic. Camera projection matches PPC's 30-degree ground plane. Audio uses imported gdfxr synthesis with cached presets, eight bounded effects voices and separate ambience/music players, plus WAV export. No remote service is required.

## Persistence

One coordinator captures actor state, equipped/bag Gloot snapshots, narrative pools and quest properties, flags, faction changes, every generated region's current tiles and mutations, projectiles and a bounded causal event history. Atomic temporary-file replacement supports three slots. Schema and generator revisions are explicit and rejected on mismatch. Snapshot validation precedes mutation; bridge staging/rollback preserves a running session if restore fails. Full region arrays are stored in v1: this is a simple, reliable baseline rather than an unimplemented claim of delta streaming. Cross-region container/actor IDs remain stable.

See the integration map for exact source origins, responsibilities and extension files. Save formats and engine pinning are implementation contracts; upgrades require deliberate migrations.

## Android and input authority

`Foundation.GameplayBlocked` gates movement, abilities, interactions and quick items for all devices. Pack management uses `CanManageItems`, allowing inspection/configuration in a pack while rejecting mutations under dialogue, pause, focus loss or death. Touch movement owns one finger; raw hotbar touch dispatch permits a second finger without relying on mouse emulation. Modal/focus changes cancel held movement. Background autosaves are separate from manual slots.

Persistent narrative flags retain historical defeat totals before acceptance. Item acquisition objectives reconcile current Gloot possession on acceptance; crafting stays an after-acceptance objective. Reconciliation invokes the normal completion/reward path once, rather than replaying past events.

## Combat presentation

`AttackStarted` starts one timed PPC `ActionPlayer`; `AttackCommitted` never restarts it. An authored `ActionStyle` selects an existing PPC style, while omitted or appendage-incompatible styles fall back to the rig default. `MatchCombat` aligns the strike envelope with the authoritative windup and recovery; each view sync derives pose and sword-trail progress from the world’s remaining action time, including frames that advance several world ticks. Cancel and hit clear both active and pending actions. Rebuilding a view reconstructs an ongoing windup from its remaining world time, without emitting another event or sound; completed recovery is not replayed. The attacker keeps the committed cone/slash yaw or tracks its target as before. Hit direction uses the event's source and captured pre-knockback position and never requests a new victim-facing direction.

`CreatureActor.ActionAnimationFps` is bounded to 60 and defaults to 30 in character views. Attacks, the first 0.38 seconds of a hit reaction, and the existing biped roll use the higher of that rate and the normal pose rate; idle and locomotion retain their existing rates. Culled actors still skip rasterization. The existing render queue snapshots the latest pose and joins worker rasterization before uploading textures on the main thread, so an older asynchronous result cannot overwrite a later pose. Neither the world tick nor authored combat durations change.

`CombatEffects` is one projected, world-anchored draw layer. It stores at most 48 effects, with at most seven generated fragments each, and expires them within 0.64 seconds. High-priority deaths/heavy hits may replace lower-priority effects; otherwise overflow is dropped. Event-derived hashes vary shapes without using gameplay randomness. The controller clears temporary effects on view/region reconstruction and suppresses a same-tick miss corresponding to an avoidance. A fatal hit produces one hit reaction and a separate, subdued death accent; the rig then enters its existing anatomy-aware rest posture. A restored corpse snaps to that posture without replaying the fatal event, remains in `World.Actors`, and keeps its loot indicator.

Combat sound resources are synthesized once at startup. Eight reusable effects players allow at most two simultaneous instances of a kind; important cues may replace lower-priority voices, and nearby combat takes precedence over distant sources. All players use the existing master bus and mute; scene/view resets stop transient voices without stopping ambience or music. `CameraFeedback` adds a bounded, decaying offset after the ordinary follow target is chosen; its strength can be set to zero, its offset is confined to region bounds, and resets clear it without changing the player or resetting camera smoothing. Godot's follow smoothing runs on fixed physics callbacks with the same configured follow speed: the idle-frame callback could extrapolate far beyond its target when a rendered frame stalled.

## Part 4 controls and observation

`MobileCombatControls` supplies stable action registration, pure layout geometry and physical-to-logical safe-area conversion. RpgUi owns touch dispatch and panels; Foundation keeps the actual commands. Layout changes and modal/focus transitions synchronously clear finger ownership. Interact emphasis uses Foundation's shared merchant predicate and World.InteractionTargets/LootTargets, the same queries used to dispatch interactions.

`PlayerLocator` is a cosmetic, world-projected small ground ring only while two hostile living bodies are within 48 ground units. It does not change targeting, collision, visibility knowledge, damage or saves. Spit's pale outer rim is also purely cosmetic. The reversible combat lab now supports normal-health and protected single/mixed/crowded fixtures. Existing snapshot restore remains the sole isolation mechanism; temporary actors cannot enter normal progression saves.

## PR5 dungeon spatial adapter

Graph Dungeon Generator owns mission grammar and logical layout. `DungeonLayout` carves it into terrain: each layout cell owns a 17-tile block with a solid ring; mission cells become rooms (a 9×9 core plus optional wings), connection cells become 3×3 halls, and every reciprocal edge becomes a three-tile corridor that may turn once on each side. Shapes and bends come from a separate integer hash, never mission RNG draws. See [DUNGEON_LAYOUT.md](DUNGEON_LAYOUT.md) for the full contract.

A gate occupies both ring rows of its passage across the complete three-tile corridor (six floor cells with `lock` features). `RegionState.GateGroups()` derives sorted cardinal connected components from serialized features. Passages stay four tiles clear of block corners, so different gates cannot touch. Runtime interaction, mission validation and gate presentation share this membership. One key opens every member; opened cells remain in `OpenDoors`. The validator can return a deterministic gate-plan witness and accepts an existing key balance for validating mutated saved states.

Saved regions store their full tile arrays plus `Rooms` and `Passages`; no restore path calls the dungeon generator. The generator identity is `rpg-regions-2`; saves from an earlier generator are rejected rather than migrated. No collision radii, tile size, controls, movement/combat timing, enemy profiles or spawn counts are retuned. The existing placement/path algorithms remain authoritative. Ruin entry uses FindPlacement to stand clear of the return marker and surviving actors; snapshot restore preserves saved actor positions.

### Wall depth correction after Part 1 phone feedback

Raised `Terrain.Wall` geometry is no longer part of the background terrain mesh. `TerrainWallRow` creates one mesh/node per nonempty tile row in the same Y-sorted container as CharacterView and FeatureView. Its sorting anchor is the projected front ground edge `(row + 1) * Tile`, independent of the 14-pixel cap rise. A character behind that edge is drawn before the opaque wall; a character in front is drawn afterward. Each mesh contains only actual wall columns, retaining doorway gaps. Floors remain batched in the background; natural-rock rendering remains unchanged.

This is presentation only: no terrain, footprint, actor position, movement, gate or persistence rule changes. Row meshes are built on region presentation rebuild, bounded by region height, and removed on region transitions. Hiding characters for verification leaves wall meshes visible. Terrain construction measurements include both the floor batch and wall-row mesh construction.

## PR5 Part 3 room composition

`Landmarks` applies validated JSON room compositions after the existing graph/layout/solvability pass, inside new dungeon generation only. Independent revisioned integer hashes select compatible role/mask/orientation candidates, without consuming upstream RNG. Protected cross/perimeter lanes, real radius-11 sweeps, feature clearance, bounded candidate rollback and safe-open fallback preserve traversal. Mission landmarks reserve architecture nodes first. RegionState stores the resolved composition alongside authoritative tiles; restoration never reruns templates. Renderer-only theme tints reuse floor/wall atlases; one shared prop atlas and static ground-details mesh extend the Part 2 pipeline. See [LANDMARK_AUTHORING.md](LANDMARK_AUTHORING.md) and [PR5_PART3_HANDOFF.md](PR5_PART3_HANDOFF.md).
